## Environment dependencies

```bash
pip install numpy pandas matplotlib scikit-learn torch rdkit tqdm Pillow
```

- Fig 2/3/5/6/7 only need numpy + pandas + matplotlib (no torch/rdkit required)
- Fig 4 inference needs torch + rdkit + tqdm + Pillow; when the npz is already cached, `fig4_plot.py` does not need torch

## How to run

```bash
python fig2_smiles.py        # → fig2a_smiles_parity.png, fig2b_smiles_cv.png
python fig3_benchmark.py     # → fig3_benchmark_mean_r2.png
python fig5_xai.py           # → fig5_xai_smiles.png
python fig6_crossdft.py      # → fig6_crossdft.png
python fig7_case_study.py    # → fig7_hd.png

# Fig 4 (on a GPU server, two steps are recommended to isolate it from the plotting process):
python fig4_infer.py --xyz     # 3D GAT inference → fig4_xyz_results.npz
python fig4_infer.py --smiles  # SMILES GAT inference → fig4_smiles_results.npz
python fig4_plot.py            # plotting only → fig4_physics_hd.png
# or all in one go (works on CPU too, just slower):
python fig4_infer.py           # if the npz already exists, skip inference and plot directly
```

## Adjusting the layout

All figures are set up in the large-canvas format of `benchmark_comparison_v3.ipynb` (large figsize 16–20in + large fonts
13–20pt + bar-top/scatter annotations + dpi 600). Each script has a `# ============ layout parameters ============` section at the top
that holds the canvas size (FIGW/FIGH), the DPI and the font sizes for each level. After changing them, just re-run the corresponding script; the numerical verification lines tell you whether the numbers changed.

- Figure looks too small → increase `FIGW`/`FIGH` (panels scale proportionally)
- Font looks too small → increase the corresponding `FS_*`
- Fig 3 outputs 3 figures (grouped bar chart / Mean R² overview / Dipole head-to-head), notebook cell 3/4/5 layout
- The 8-panel figures (Fig 2a / Fig 6) are currently 4 rows × 2 columns vertical; to switch to a 2×4 horizontal layout, change `plt.subplots(4, 2, ...)` to `(2, 4, ...)`
- Label/value overlap issues have been fixed in the final version: Fig 2b top two subplots x labels rotation 35 (FS_B_XTICK=11), bottom-right subplot legend columnspacing=3; Fig 3 grouped bar chart legend moved below the figure outside (bbox_to_anchor, ncol=4), ylim 1.12; Fig 4 panel (e) legend moved below the panel in a horizontal row (ncol=2), tight_layout rect=[0,0.09,1,1]; Fig 5 panel (a) value labels vertical 8pt (FS_BAR_A=8), element labels vertical 11pt, panel (e) x labels FS_XTICK_E=12; Fig 7 bar-top values vertical 12pt (FS_VAL_3D=FS_VAL_SM=12), negative values placed below the bar bottom, legend ncol=3 horizontal. Reverting these changes causes overlap

## Important notes

- **The SMILES panel of Fig 4** uses `models/tmqm_gat_best_backup.pt` by default (July 20 version).
  The final numbers 0.20 mHa / 99.7% <0.001 Ha come from this checkpoint; `tmqm_gat_best.pt` (July 15 version)
  gives 0.14 mHa, which does not match the main text. **Do not swap the checkpoint**.
- The prediction caches in `data/` are training-time artifacts read directly by the scripts; do not overwrite them with new training results
  (otherwise the numbers in the figures change and no longer match the main text).
